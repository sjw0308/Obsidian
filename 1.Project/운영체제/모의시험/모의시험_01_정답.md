# 운영체제 중간고사 모의시험 1회 정답·해설

- 제한시간: 80분 / 총점: 100점
- 부분점수: 아래 배점을 기준으로 핵심 개념과 올바른 계산 과정에 부여합니다.
- 단위가 생략된 스케줄링 계산은 문제의 시간 단위를 따릅니다.

## 1. OS와 실행 파일 (10점)

가: 가상화는 물리 자원을 추상화하여 각 작업에 CPU·주소공간 등을 제공한다. 동시성은 실행 흐름 간 공유 자원의 올바른 접근을 다룬다. 영속성은 전원이 꺼져도 데이터를 보존한다. 각 2점.

나: 컴파일러(C→어셈블리), 어셈블러(→오브젝트), 링커(→실행 파일). 초기화 전역변수는 .data, 미초기화 전역변수는 .bss. 단계 2점, 영역 각 1점.

## 2. 프로세스와 제어권 (10점)

가: fork는 새 프로세스를 만들고, exec는 호출한 프로세스의 실행 프로그램·주소공간을 새 프로그램으로 교체한다(새 프로세스를 만드는 호출이 아니다). 각 2점.

나: Running→Blocked→Ready. 완료 즉시 Running이 되는 것은 아니며 선택되어야 실행한다. 3점.

다: 타이머 인터럽트가 커널 핸들러로 제어를 넘기고 스케줄러가 다른 프로세스를 선택할 수 있다. 3점.

## 3. 스케줄링 계산 (20점)

가: SJF A[0,8), C[8,10), B[10,14). STCF A[0,1), B[1,2), C[2,4), B[4,7), A[7,14). 각 4점.

나: SJF turnaround(A,B,C)=(8,13,8), 평균 29/3. STCF=(14,6,2), 평균 22/3. 각 정책 작업별 3점+평균 1점.

다: SJF response=(0,9,6), STCF=(0,0,0). 각 2점.

## 4. MLFQ와 RR (10점)

가: 다른 작업이 CPU를 받기까지 대기시간은 대체로 줄지만 전환 횟수와 비용 비중이 커진다. 4점.

나: 낮은 큐 작업의 starvation. 주기적으로 우선순위를 올려 실행 기회를 주고 작업 성격 변화도 반영한다. 3점.

다: I/O로 양보해도 같은 우선순위에서 누적 CPU 사용량을 유지하고 총 할당량 소진 시 강등한다. 3점.

## 5. Race condition (10점)

가: T1 load 0, T2 load 0, T1 add→1, T2 add→1, T1 store 1, T2 store 1. 4점.

나: 1 또는 2. load부터 store까지 전체 read-modify-write를 하나의 락으로 보호한다. 3점.

다: PC·레지스터(각 스레드의 스택도 별도), 주소공간·열린 파일 자원 공유. 3점.

## 6. 하드웨어 락 (10점)

가: lock: while(TestAndSet(&flag,1)==1) {} / unlock: flag=0; 원자 연산 및 올바른 메모리 가시성을 가정한다. 각 2점.

나: FetchAndAdd로 발급한 번호 순서대로 turn을 기다리므로 FIFO 획득. 대기 중 spinning으로 CPU를 쓴다. 3점.

다: 아니오. 다른 CPU는 계속 실행하며 같은 공유 메모리에 접근할 수 있다. 3점.

## 7. 세마포어와 bounded buffer (15점)

가: empty=N, full=0, mutex=1. 각 1점.

나: producer wait(empty)→wait(mutex)→put→post(mutex)→post(full). consumer wait(full)→wait(mutex)→get→post(mutex)→post(empty). 각 4점.

다: 버퍼가 가득 찬 상태에서 producer가 mutex를 소유하고 empty를 기다리면 consumer는 mutex를 얻지 못해 버퍼를 비우지 못한다. deadlock. 상황·순환 대기 각 2점.

## 8. 데드락 (15점)

가: mutual exclusion(락 단독 소유), hold and wait(하나 소유하며 다른 것 대기), no preemption(강제 회수 불가), circular wait(T1→T2→T1). 각 2점.

나: 모든 스레드가 L1 다음 L2 순으로 획득하게 해 circular wait를 없앤다. 4점.

다: 두 스레드가 획득·해제를 반복해 진행하지 못하는 livelock. 무작위 backoff가 완화에 도움을 준다. 3점.
