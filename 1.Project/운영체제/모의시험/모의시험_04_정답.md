# 운영체제 중간고사 모의시험 4회 정답·해설

- 80분 / 100점 / 8문항
- 신규 범위: Multi CPU Scheduling (6~8번, 40점).
- 문항의 명시적 가정을 기준으로 채점하며, 동등한 설명·유효한 실행 순서도 인정합니다.
- 각 소문항은 표시된 요소별로 부분점수를 부여합니다.

## 1. 프로그램·프로세스·스레드 (10점)

(가) .c→컴파일러→.s→어셈블러→.o→링커→실행 파일(2점). 초기화 전역변수 .data, 미초기화 전역변수 .bss(각 1점).

(나) 공유: 가상 주소공간, 열린 파일 자원(각 0.75점). 별도: PC, 레지스터(각 0.75점). 별도 스택도 인정한다.

(다) Running→Blocked→Ready/Runnable→Running(2점). I/O 완료는 실행 가능 상태로 만들며 스케줄러가 선택해야 실행한다(1점).

## 2. RR와 CFS 모델 (15점)

(가) A[0,2), B[2,4), C[4,6), A[6,8), C[8,9)(2점). turnaround(A,B,C)=(8,4,9)(2점), response=(0,2,4)(2점).

(나) A 선택 후 (24,21), B 선택 후 (24,23). 증가량은 기준 weight/작업 weight×실행시간. 선택 각 1점, 각 벡터 1점, 올바른 증가량 계산 1점.

(다) max(20/8,3)=3ms(2점), 한 순환 8×3=24ms(2점). 실제 구현 전반에 대한 주장이 아니라 지정 모델 계산이다.

## 3. MLFQ의 실행 추적 (10점)

(가) A[0,2), B[2,3), A[3,7). A는 Q0 할당량 2를 소비하여 시각 2에 Q1으로 이동한다. B의 Q0 도착은 같은 우선순위의 A를 즉시 선점하지 않는다. 세 구간 각 1.5점, A의 Q1 이동 2.5점.

(나) 낮은 우선순위의 starvation 완화(1.5점), CPU 중심에서 interactive로 성격이 바뀐 작업의 우선순위 회복(1.5점).

## 4. 락의 정확성과 대기 (10점)

(가) T1이 flag=0 확인→T2도 0 확인→T1 store 1→T2 store 1→둘 다 진입. 확인과 설정이 별도여서 같은 빈 상태를 함께 관측한다. 유효 순서 3점, 원인 1점.

(나) A 큐 등록/guard 해제→B가 A unpark→A park로 잠들어 알림을 놓침(2점). 큐 등록 후 guard 해제 전에 setpark하여 이후 unpark를 다음 park가 기억하게 한다(2점).

(다) 아니다(1점). guard는 공유 메타데이터 접근을 상호배제하며, 별도 인터럽트 제어 없이는 선점 자체를 막지 않는다(1점).

## 5. 세마포어·공정성·진행 (15점)

(가) wait(full)→wait(mutex)→get→post(mutex)→post(empty)(2점). full=소비 가능한 데이터 수, empty=생산 가능한 빈 슬롯 수, mutex=버퍼 조작 상호배제(각 1점).

(나) reader가 겹쳐 계속 도착하면 readers가 0이 되지 않아 write_lock이 반환되지 않는다. writer가 무한히 기다릴 수 있다. 상황 3점, starvation 판단 1점.

(다) 서로 획득·반납을 반복하며 진전 없는 livelock 가능(2점). 무작위 backoff 등으로 동기화된 재시도를 완화한다(2점). 전역 순서는 circular wait 제거(2점). backoff만으로 모든 실행의 공정성이 보장되는 것은 아니다.

## 6. Amdahl의 역산 (10점)

(가) 1/2.5=S+(1-S)/4이므로 0.4=0.25+0.75S, S=0.2. 식 2점, 값 2점.

(나) 1/(0.2+0.8/N)≥4 →0.8/N≤0.05 →N≥16. 최소 16코어. 부등식 2점, 최소값 1점.

(다) 1/(0.05+0.95/8)=160/27≈5.93배. 식 1.5점, 계산 1.5점.

## 7. MQMS의 부하 분산 추적 (20점)

(가) CPU0 A[0,8),B[8,12); CPU1 C[0,2),D[2,4),idle[4,12). 구간 4점, makespan=12(2점), 합산 idle=8(2점).

(나) 시각 4에 B를 steal한다. CPU0 A[0,8), CPU1 C[0,2),D[2,4),B[4,8). 구간 4점, makespan=8(2점), 합산 idle=0(2점).

(다) 원격 큐 탐색·동기화 경합, migration에 따른 cache affinity 손실 등 각 2점. 작업 이동이 항상 성능 개선으로 이어지는 것은 아니다.

## 8. 멀티코어 설계 판단 (10점)

(가) 틀리다(1점). owner와 stealer가 같은 큐를 동시에 수정할 수 있다(2점). 락 또는 올바른 동시성 큐 같은 조정이 필요하다(1점). per-CPU 큐가 모든 경로를 자동으로 lock-free로 만들지는 않는다.

(나) CPU0에 cache가 데워진 작업이 몰리고 CPU1은 idle인 상황. CPU0 유지로 locality는 좋지만 부하 불균형, CPU1 이동으로 병렬 이용은 늘지만 cache 재가열 비용이 생긴다. 상황과 두 효과 각 1점.

(다) 분할된 데이터에 같은 연산을 적용하므로 data parallelism(1점). 병합 전 모든 필요한 부분 결과가 완료되고 관측 가능해야 하며 join·완료 세마포어 등의 동기화로 보장한다(2점).

## 다중 CPU 핵심 주의사항

- Cache coherence와 복합 연산의 원자성은 구분해야 합니다.
- MQMS는 큐 경합을 분산하지만 migration·work stealing 시 동시 접근에 대한 설계가 필요합니다.
- Amdahl 계산은 고정 작업 크기와 문제에 지정된 비용 모델에 한정합니다.
