# 운영체제 중간고사 모의시험 3회 정답·해설

- 80분 / 100점 / 8문항
- 신규 범위: Multi CPU Scheduling (6~8번, 40점).
- 문항의 명시적 가정을 기준으로 채점하며, 동등한 설명·유효한 실행 순서도 인정합니다.
- 각 소문항은 표시된 요소별로 부분점수를 부여합니다.

## 1. 프로세스와 커널 진입 (10점)

(가) fork는 새 프로세스를 생성한다(2점). exec는 호출 프로세스의 프로그램·주소공간을 교체하며 성공 자체로 프로세스 수를 늘리지 않는다(2점).

(나) 자발적인 syscall·양보를 하지 않는 작업도 있을 수 있다(1점). 타이머 인터럽트로 커널이 주기적으로 제어권을 회수해 스케줄링할 수 있다(2점).

(다) 사용자→커널→사용자 모드 전환은 있다(1.5점). 같은 프로세스가 계속 실행되면 다른 프로세스로의 context switch는 필수가 아니다(1.5점).

## 2. SJF와 STCF 계산 (15점)

(가) SJF: A[0,6), C[6,7), B[7,9). STCF: A[0,1), B[1,3), C[3,4), A[4,9). 시각 2에 B와 C의 남은 시간이 1로 같아 B가 유지된다. 정책별 3점.

(나) SJF turnaround(A,B,C)=(6,8,5), 평균 19/3. STCF=(9,2,2), 평균 13/3. 정책별 작업별 값 2점, 평균 1점.

(다) STCF response(A,B,C)=(0,0,1). 각 1점.

## 3. MLFQ와 비례 배분 (10점)

(가) 할당량 직전 I/O 양보를 반복해 강등을 피한다(2점). 같은 큐에서의 CPU 사용량을 양보에 걸쳐 누적하고 총 할당량 소진 시 강등한다(2점).

(나) A의 기대 비율 1/4=25%(1.5점). 추첨은 확률적이므로 유한한 4회에서 정확히 한 번은 보장하지 않는다(1.5점).

(다) 기존 작업의 pass가 크면 신규 작업이 따라잡을 때까지 연속 선택될 수 있다(1.5점). 신규 pass를 현재 runnable 작업의 최소 pass에 맞추는 등의 보정(1.5점).

## 4. 경쟁과 ticket lock (10점)

(가) 예: T1 load 0/add 1→T2 load 0/add 1/store 1→T1 store 1(3점). 같은 락으로 load-add-store 전체를 보호한다(2점). 다른 유효한 interleaving도 인정한다.

(나) 번호는 T1=0,T2=1,T3=2, 최초 진입자는 T1, 첫 해제 후 turn=1. 각각 1점.

(다) 기다리는 스레드가 계속 spin하여 CPU 시간과 메모리 계층의 자원을 소비한다. 2점.

## 5. 세마포어와 데드락 (15점)

(가) s=0(1점), 부모는 결과 사용 전 wait(s)(1점), 자식은 기록 완료 후 post(s)(1점). 자식이 먼저 post해도 허가가 남으므로 안전하다(1점).

(나) empty=N, full=0, mutex=1(각 1점). 가득 찬 버퍼에서 producer가 mutex를 보유한 채 empty 대기, consumer는 mutex를 못 얻어 버퍼를 비울 수 없다(2점).

(다) 단독 소유=mutual exclusion, 보유하며 추가 대기=hold and wait, 강제 회수 불가=no preemption, T1→T2→T1=circular wait(각 1점). 모두 L1→L2 순으로 획득하여 원형 대기를 제거한다(2점).

## 6. 병렬성의 종류와 의존성 (10점)

(가) concurrency는 여러 실행 흐름의 진행이 시간상 겹치는 것이고 단일 코어 interleaving으로도 가능하다. parallelism은 실제 동시 실행으로 여기서는 여러 코어가 필요하다. 구분 2점, 단일 코어 판단 1점.

(나) 배열 분할은 data parallelism: 데이터 조각에 같은 연산(2점). 독립적인 서로 다른 연산 분담은 task parallelism(2점).

(다) 안 된다(1점). B는 A의 완료 및 출력 가시성이 보장된 뒤 시작해야 한다(2점). 공유한다는 사실만으로 의존성이 해소되지 않는다.

## 7. Amdahl 계산과 최적화 (20점)

(가) T4=100×(0.2+0.8/4)=40초(4점), speedup=100/40=2.5(4점).

(나) N→∞이면 1/S=5배. 6점.

(다) 8코어: 1/(0.2+0.8/8)=10/3≈3.33배(2점). S=0.1, 4코어: 1/(0.1+0.9/4)=40/13≈3.08배(2점). 주어진 두 안에서는 8코어가 더 빠르다(2점). 직렬 부분 축소가 언제나 코어 추가보다 좋은 것은 아니다.

## 8. SQMS·MQMS와 cache (10점)

(가) 여러 코어가 같은 큐를 선택·수정하므로 보호 및 직렬화 비용이 커진다(2점). 작업이 다른 코어로 배정되면 기존 cache 내용의 이점을 잃는다(2점).

(나) 일반적인 로컬 큐 접근이 분산되어 공유 큐 경합이 감소한다(1.5점). 큐별 남은 작업량이 달라 일부 코어가 idle인데 다른 코어에 일이 남을 수 있다(1.5점).

(다) 불필요하다는 주장은 틀리다(1점). coherence는 여러 cache의 일관성을 다루며 load-add-store 전체의 원자성을 보장하지 않는다. 락 또는 원자적 증가 연산이 필요하다(2점).

## 다중 CPU 핵심 주의사항

- Cache coherence와 복합 연산의 원자성은 구분해야 합니다.
- MQMS는 큐 경합을 분산하지만 migration·work stealing 시 동시 접근에 대한 설계가 필요합니다.
- Amdahl 계산은 고정 작업 크기와 문제에 지정된 비용 모델에 한정합니다.
